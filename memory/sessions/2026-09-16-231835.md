Eric asked for a review of `/tmp/agent-memory-open-thread-staleness-report.md` (mercury-composable
team, agent-memory v4.39.2, 2026-09-16). Finding: an unchecked Open Thread is exempt from decay by
design, and that exemption also removed the only automated freshness signal — a pinned thread in their

`thread_stale_window` knob (default 40); (2) a REVIEW.md step that re-reads unchecked bodies; (3) a
guidance line naming the anti-pattern — a checklist nested inside a record whose lifecycle differs from
the items' (their second instance: a release commitment inside a wholesale-rewritten status field).
They offered a PR.

**Verified against source — every claim holds.** DECAY.md §5 rule 4 is quoted verbatim; memory-lint's
14-check inventory matches exactly and none inspects an open thread's age or body; `refresh-metadata`
already refreshes `uses`/`last_used` on pinned threads and skips only the tier (v4.26.1), so the

only the Contradiction backstop's "reads every fact anyway" assumes a re-read; the v4.24.0 precedent
("the cadence trigger only ever fired in the agent's head") is the same failure class.

**Dogfood confirms it.** This repo: 20 unchecked threads, 176 sessions. Sessions since last reference —
`bp-sdlc-overlay` 151, `vbdi-lifecycle-direction` 89, `ot-before-session-cursor-kiro-backlog` 37,

never-checked" callout gives core + invariants a 40-session human re-check and omits the third
never-decay class in the same list. Session-start reads of thread bodies are for orientation, so they
prime trust, not audit.

**Review notes given.** (a) The proposal needed a defined acknowledgment path — the only reset for

altitude transition that DECAY.md §12 already reserves for a human. Resulting shape, recorded in the new
thread: knob + lint advisory for detection; a REVIEW.md step mirroring step 7 that raises one
`Close stalled threads (due)` gate thread listing each stalled id; the human closes (`[x]` + 3–6-line
